# Contributing to NEXVARY AeroRadar

AeroRadar is a civil aviation research and **simulation-only** project.
All data generated by the current engine are synthetic.

## Workflow

1. Develop on a feature or quality branch; never commit directly to `main`.
2. Open a **draft pull request** against the relevant parent branch.
3. Link the GitHub issue, full commit SHA, CI runs, tests, and any screenshot evidence.
4. Keep changes focused, reversible, and reviewable; do not bundle a full UI rewrite with unrelated refactoring.
5. Do not merge or distribute private-owned components without the owner's authorization.

## Design and code rules

- C++20 simulation core is independent from Qt and GUI technologies.
- Document every numeric unit, coordinate frame and time basis. Synthetic flight data must never be confused with real traffic.
- Protect reproducible simulation behavior with deterministic tests in **Debug and Release**.
- A `Q_PROPERTY` must notify QML when its value changes; GUI controls must execute real actions or be visibly marked as placeholders.
- Prefer reusable QML components over a monolithic `Main.qml`.
- Use `.editorconfig` and `.clang-format` as shared style baselines; formatting enforcement follows a separate source-formatting review.
- Check third-party licenses for source, icons, fonts, data providers, models, and Qt libraries.
- Never commit secrets, private source, or offensive avionics/CUAS capabilities to the public repository.

## Required validation

See [Engineering Quality Policy](docs/CODE_QUALITY_POLICY.md).
Run these locally as applicable:

```sh
python3 tools/check_source_hygiene.py
cmake -S . -B build-debug -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug
ctest --test-dir build-debug --output-on-failure
cmake -S . -B build-release -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --config Release
ctest --test-dir build-release -C Release --output-on-failure
```

For desktop changes also build the Qt target and verify the actual startup smoke test on Windows and Linux. A green compile alone is insufficient proof of GUI behavior.

## Review standard

Draft PRs remain unmerged until CI and real evidence are complete and the owner approves the integration. See the repository pull-request template for the checklist.
